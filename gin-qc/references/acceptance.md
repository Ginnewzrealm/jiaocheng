# v3 验收记录

四个维度独立输出：可执行性（步骤契约）、可验证性（实际观察）、覆盖完整性（目标／内容／引用）、证据可靠性（快照和支持关系记录）。结构通过不代表语义正确，人工复核仍检查遗漏断言与不当推断。

实际核验记录 verification/article-id.json：

```json
{
  "schema_version": 3,
  "article_id": "configure-tool",
  "document_sha256": "当前正文文件SHA256",
  "outline_sha256": "当前大纲文件SHA256",
  "environment": {"工具版本": "与大纲一致", "平台": "与大纲一致"},
  "checks": [{"criterion_id": "K-1", "status": "not_verified"}]
}
```

每个 criterion_id 与成功标准一一对应。实际通过后记录 status: pass，以及非空 observed、by、at、method、log、sha256：观察结果、检查者、时间、方法、相对核验文件目录的日志路径、日志哈希。日志保存实际输出或应用题作答过程；不能为清除闸门捏造。失败填 fail，尚未验证填 not_verified。

环境与契约完全一致。改正文或大纲后重新判断并执行必要核验，更新真实记录；脚本拒绝旧哈希，不自行执行教程命令，也不推断未提供的结果。

机械验收检查：

- 操作／排错步骤完整。每个 `<!-- step:ID -->` 仅出现一次，其后到下一标记或 H2 之间包含对应动作、预期结果、验证方法、失败处理。
- H2 与大纲一致，各节引用声明的结论，脚注有定义。正文有前置条件、失败边界、交付物、成功判据和概念练习。
- 围栏闭合且有语言，标题不跳级，表格列数一致，本地资源和锚点存在。
- 报告记录输入、依赖资源和检查器哈希。旧稿报告、被改过的日志和预览不能作为当前验收依据。

语义与视觉审阅至少覆盖：证据支持／学习路径／桌面成品／窄屏成品。完整通读发现“字段都有，但读者仍无法完成”的情况。用户要求人工确认时，不用自动分数取代。

status 取 pass/minor/fail；errors、warnings 始终是数组，计数一致。verdict 如存在只是展示文案。CLI：0 通过或 minor，1 质量未通过，2 输入或工具故障。失败也输出报告。
