# gin-answer：研究答案并核实证据

一题一张答案卡。先有可追溯证据，再写综合判断。开始制作卡片时读 [证据协议](references/evidence-standard.md)，按其中 v3 格式记录。

1. 运行 `python3 scripts/answer.py classify --question "问题"`，用事实型／方法型／争议型决定研究深度，保留判定依据。这是研究分类，不是教程原型。
2. 查明由来与演变、当前做法与分歧。事实问题可以简短；方法问题交代流程和变体；争议问题对齐各方证据与条件。不要为了横纵分析凑历史。
3. 将所引用来源保存到资料库，包括联网补充来源。记录原始出处标识、URL、摘录定位、范围与快照哈希。目录层级、本地保存和来源数量都不自动证明权威或独立。
4. 将关键判断拆成 claims。核对原文是否支持结论及范围，记录检查者、时间和方法；没有核过的保持未核验。冲突时比较版本、条件、方法和时效，不一律让本地资料胜出。
5. 输出研究报告与答案卡。报告交代综合判断、适用边界和未解决问题；账本保留施工细节。无法支持的断言降级或删除，不伪造摘录、验证记录或第一人称经历。
6. 运行只读检查，再由 manifest 命令生成标准化卡片：

```bash
python3 scripts/answer.py validate --card answers/问题.json --library library --output answers/问题.check.json
python3 scripts/answer.py manifest --dir answers --topic "选定主题" --library library
```

validate 不改输入卡。manifest 重新验证并复算置信度，其 cards 是下游唯一使用的版本；错误或低置信卡标为待补采，不能靠原卡自报达标进入生产。answers 目录仅放本次选定问题的卡片与 .check.json 检查报告。

置信度：显式 high 且可追溯的来源才计入权威组；同一原始出处、镜像和普通同域页面不能重复计数。无权威组为低，一组或存在争议为中，至少两组且无争议才可能为高；无资料库时上限为中。单份官方规范支持命令语法可以为中，不强求第二来源；效果比较等问题另作语义审阅。

v3 检查核对来源快照、摘录和记录完整性，不能替代判断证据是否支持结论。verified 必须来自实际完成的核对。操作是否复现留给成稿后的独立验证。

检查输出 errors[]、warnings[]、error_count、status；退出码 0 为通过或 minor，1 为质量失败，2 为输入/工具错误。报告绑定输入与检查器哈希，修改来源后重新检查。
