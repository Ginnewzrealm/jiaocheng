# gin-answer：单问题深度研究

输入一个问题 → 输出研究报告（人读）+ 答案卡（机器读）。
核心原则：**横纵骨架不变（纵轴追由来与演变，横轴列阵营与争议，交汇出判断），
但每个判断要么有出处、要么诚实标注存疑——判断全部可追溯。**

方法论来源：数字生命卡兹克横纵分析法（hv-analysis），针对"问题"而非"对象"改造。

## 何时使用 / 不适用

- 拿到 gin-question 的一个问题（或用户口头提的单个问题）要做深度研究 → 本技能
- 多个问题要跑 → 编排层循环调用本技能，本技能只处理单个问题
- 发现资料源 / 采集 URL / 找问题清单 → 各走对应技能

## 工作流程

```
1. 入口判定   python3 scripts/answer.py classify --question "..." → 定类型（事实/方法/争议）与篇幅档位，判定依据写入卡片
2. 联网搜索   纵轴（由来/演变/观念为何锁死）与横轴（当下阵营/争议点）两路子搜索，可并行子 Agent
3. 库对照     检索本地资料库相关文件；联网说法与库内 L1/L6 权威源冲突时 → 以库为准并在报告标注冲突
4. 写产物     报告 .md（结构见下）+ 卡片 .json（schema 见下）
5. 机检       python3 scripts/answer.py validate --card <卡片> --library <库路径>——errors 不归零不许交付
6. 落盘      凡被卡片引用的联网来源 → 采进 <library>/L7_研究补充/（复用 harvest-one，带来源头）
7. 汇总      编排层跑 manifest 子命令收 answers-manifest.json
```

## 篇幅档位（入口判定决定，不许一刀切）

| 类型 | 档位 | 判定标准 |
|---|---|---|
| 事实型 | 500-1000 字 | 有公认定义/算法，无对立阵营（由来一句带过，不注水） |
| 方法型 | 1500-3000 字 | 有公认流程但存在变体（流程+变体+边界） |
| 争议型 | 3000-6000 字 | 存在两个以上公开对立阵营（由来/两阵营并列/争议点/综合判断） |

## 报告结构模板

```markdown
# 问题：<原文>

> 问题类型：<类型> | 研究时间：<date> | 素材锚定：<N> 份本地源 + <M> 份补充源

## 一、问题的由来          （纵轴起点）
## 二、答案的演变/计算流程/两阵营   （按类型取对应骨架）
## 三、争议点对齐            （争议型必填：各阵营引用同一证据时分歧在哪）
## 四、综合判断              （交汇：当前最站得住的答案 + 适用边界）
## 五、出处                  （逐条：本地路径 或 URL+访问日期）
## 六、仍存疑/待补采的点      （诚实标注，不许编造）
```

## 答案卡 schema

```json
{
  "问题": "原文", "类型": "事实型|方法型|争议型", "类型判定依据": "classify 输出",
  "一句话答案": "≤80字", "答案详述": "answers/<slug>.md",
  "出处": [{"来源": "L3/xxx.md（库内相对路径）或 站名", "url": "联网来源必填",
             "要点": "一句话", "定级": "high|medium|unknown"}],
  "争议点": ["..."], "适用边界": ["..."],
  "置信度": "高|中|低", "状态": "达标|待补采"
}
```

## 置信度三级判定（validate 自动复算，不许凭感觉）

| 级 | 条件 |
|---|---|
| 高 | ≥2 个真正独立的权威源（本地库文件或定级 high）且 无未决争议 |
| 中 | 单一权威源 / 有争议点 / 权威与普通混合 |
| 低 | 权威源为 0（全是 unknown/低质源）→ 自动进观察哨 |

## 独立性硬规则（防"假多源"）

- 同域多条 = 一个来源
- 聚合转载域（搜狐/网易/新浪/百家号/头条/360doc）永远不算独立第二源，须回溯原始出处
- 关键事实必须 ≥2 真正独立来源；"A 引用 B"不算独立
- 倍数类宣称（"X 的效果是 Y 的 N 倍"）必须回查原始研究，查不到就标"网传待证"

## 观察哨（manifest 自动分级）

- 置信度低 / 状态待补采 / 独立性存疑 → 自动进 answers-manifest 观察哨段，供 Stage 2 人工复核

## 常见错误（红阶段基线实测，2026-09-06）

| 错误（基线实际发生） | 纠正 |
|---|---|
| 联网来源引用后不落盘，404 后死无对证 | 凡被引用必采进 L7_研究补充/（workflow 第 6 步，不许省） |
| 卡片本地出处写"本地库 L3/xxx"这种描述性文字 | 来源字段写库内相对路径（L3/xxx.md），validate 机检存在性 |
| 把媒体转引当原始研究引用 | 独立性硬规则 + check_independence 警告 |
| 置信度凭感觉打 | validate 自动复算，与自报不符即警告并回写 |
| 类型拍脑袋 | 必跑 classify，判定依据写入卡片 |
| 争议型偷懒写成"综合一下" | 报告第三节强制争议点对齐：各阵营对同一证据的分歧必须显式列出 |
| 搜不到的信息硬编 | 报告第六节标"暂缺/待补采"，卡片状态置"待补采" |

## 依赖

- 可选：本地资料库路径（harvest 产出；无库则全部出处为联网来源，置信度上限"中"）
- 联网：WebSearch/WebFetch，或 tavily（复用 gin-tutorial-source-scan 的 key 配置）
- 落盘：gin-tutorial-harvest 的 harvest-one（采联网来源进 L7/）
- 上游：gin-question 的问题清单；下游：Stage 4 大纲（读 answers-manifest.json）
