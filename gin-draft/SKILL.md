# gin-draft：教程单篇写作（篇构件）

按大纲施工单写**一篇**正文（v2 一题一文：一张达标卡 = 一篇文章，5–8 个小节）。
核心原则：**篇是装配无关的构件——本技能只管"这篇本身合格不合格"，不管它最后属于谁。**

方法论来源：X 三篇对标实拆（LanyXiaosheng / AdrianPunk115 / miles_mazy）的可机检
风格规则 + 卡兹克文风禁区词表（hv-analysis 现成表）。

## 边界声明（设计决策，用户认可）

- 本技能只生产**篇构件**，一篇 = 大纲.json 全篇，小节 = 成稿 H2。
- 装配（串篇/组书/全书结构）是上层的事，未来书籍装配层**不动本脚本一字**。
- 篇用得好不好（人物融入度、节奏、活人感）归 Stage 6 质检，本层只机检可机检项。

## 何时使用 / 不适用

- 大纲在手（gin-outline v2 已机检通过），按图施工写某一篇 → 本技能
- 还没有大纲 → 先 gin-outline（本技能不内嵌排大纲）
- 要终稿质检 → Stage 6（本层过了不等于能发）

## 工作流程

```
1. 读施工单  大纲.json 全篇：问题、标题、写给、读完能、贯穿人物（可选）、
           小节[]（每节的标题/干什么/证据）、素材[]（从卡片出处继承的库内文件）
2. 读素材    从资料库读齐素材文件（卡片给论点骨架，素材给论据血肉）
3. 写正文    篇首契约（写给+读完能，前 5 行内）→ 按小节表逐节施工
           （小节标题 = H2，"干什么"列 = 该节演什么）→ 贯穿人物穿插
           → 最后一节回收开头场景（大纲方法论 §4.4）→ 篇末交付物
4. 机检      python3 scripts/draft.py check --file <篇.md> --materials <n或路径列表>
             [--library <资料库>] [--case <贯穿人物名>]
             → errors 不归零不出件
```

## 风格规则（全部来自三篇对标实拆 + 基线实测，机检可判）

| # | 规则 | 机检 |
|---|---|---|
| 1 | 篇首两件套：写给谁 + 读完能做到什么（前 5 行内） | ❌ 缺契约不出件 |
| 2 | 篇末可拿走交付物：自查清单 / 判断表格 / 可复制模板 | ❌ "本篇要点"不算 |
| 3 | 贯穿人物出场 ≥1 次（施工单钉了人物才检；没钉不检） | ❌ 零出场不出件 |
| 4 | 素材锚定率 ≥60%：关键论断带来源标注（出处/《名》/研究（年份）/L 路径） | ❌ <60% 不出件 |
| 5 | 「不是A，是B」密度 ≤2 次/篇——单句是好修辞，密了是口头禅 | ⚠️ 超了警告 |
| 6 | 卡兹克禁区词表：说白了/本质上/换句话说/不可否认/意味着/赋能/抓手/打造闭环/综上所述/首先/其次/最后/值得注意的是/不难发现/在当今/随着技术 | ⚠️ 命中警告 |
| 7 | **回环呼应**（hv-analysis 契诃夫之枪）：篇末散文（非预告行）必须回扣篇首关键词或贯穿人物 | ❌ 缺了不出件 |
| 8 | **用人话写**（hv-analysis）：具体细节代替概括，"取得了显著进步"类空洞概括直接拦 | ❌ 命中不出件 |

## 机检规则溯源（红阶段基线实测，2026-09-06）

基线 = /tmp/gin-draft-baseline/ch1.md（"平台期"第一章裸写）五条真实失败：

| 失败 | 规则 |
|---|---|
| F1 开篇直接讲故事，没写给谁 | 规则 1 篇首契约 |
| F2 章末只有"本章要点" | 规则 2 交付物 |
| F3 大纲钉了"小张"，正文零出场 | 规则 3 人物在场 |
| F4 通篇论断零出处 | 规则 4 锚定率 60% |
| F5 「不是A是B」一章 5 次 | 规则 5 密度上限 |

## 锚定率口径（防凑数，重构期实测）

- 分母 = 本篇素材份数 × 2（每份素材 2 处锚点 = 满分），封顶 100%。
- 宽口径命中：「素材：」「出处：」「根据《×》」「（含年份）」「L1-L7/ 路径」「研究表明/发现/显示」。
- **只堵清单式贴名**：头部带"素材/出处/来源/参考/引用"标签的行、或一行并列 ≥2 个
  L 路径（、/，连接）的行，最多算 1 锚点——锚定必须分布在正文里，不能篇末贴一行糊弄。
- 正文里一句真引用连标几处照实计数（一句话多处标源是好的）。

## 口吻选择（按问题类型，不写进机检）

- 事实型/解释型 → miles_mazy 解释者风（第一人称集中，拆解给外行听）
- 方法型/争议型 → Lany / Adrian 案例实战风（反向判断密度高：不必/不要/没必要/不适合）
- 共性：NextSteps 结尾、数字具体到个位数（"3 周"不写"一段时间"）

## 教程排版构件（2026-09-12 调研批次：按大纲"构件"字段施工）

大纲.json 每节有可选"构件"字段（gin-outline §4.5），施工时按构件呈现——
这是"像教程"和"像散文"的分水岭：

| 构件 | 施工方式 |
|---|---|
| 步骤表 | 有序列表 `1. 2. 3.`，每项**动作开头**："算出你的 TDEE"✅ "TDEE 的计算"❌ |
| 对比表 | markdown 表格，维度 ≥2 列，表头人话 |
| 提示块 | 引用块 + 前缀：`> **注意**：…` / `> **坑**：…`——坑/反常识/易错点才用，不要满地提示块 |
| 代码块 | 围栏标语言（```python / ```bash），内容可直接复制 |
| 无 | 纯散文 + H2（默认） |

**H3 用法**：只有节内出现步骤分组、需要导航时才上 H3；标题层级不跳级（H2 下
直接 H4 ❌）；H3 不孤儿（全文单个 H3 无配对 ❌）。5-8 节的单篇大多不需要 H3。

**加粗**：关键句加粗，≤2 处/屏；满地加粗 = 处处强调 = 无强调。

**篇首契约排版**：写给/读完能可以融入导语后单独成引用块
（`> **写给**：…` / `> **读完能**：…`），视觉上是教程构件而不是课程大纲——
契约机检只认"写给/读完"字样，引用块样式不影响判定。

## 写作指引（hv-analysis 报告文体吸收，2026-09-06 用户拍板）


以下不进机检（判不了），写作时主动执行、Stage 6 L4 人审把关：

- **叙事驱动非罗列驱动**：篇要有故事弧线（贯穿人物天然承担），不写流水账
- **层层剥开**：现象 → 表面解释 → 更深的追问 → 核心洞察，让读者参与推理
- **谦逊铺垫**：给建议前先卸傲慢（"我也不确定，但我的经验是…"），教程文尤其需要
- **对立面承认**：说"你该怎么做"之前，先承认"不这么做的人也合理"
- **知识随手掏**：背景知识在论述中自然带出，不"下面我来科普一下"
- **敢下判断**：先摆事实再给判断，推测要明说（gin-qc 有机检），姿态用"我的判断是"而非居高临下
- **按节施工**：每节对照施工单"干什么"列写——那列写不出场景的小节在大纲阶段就该删了，
  施工时若发现某节真的没东西可演，停下来回报，不要硬凑

## 常见错误（红阶段基线实测）

| 错误（基线实际行为） | 纠正 |
|---|---|
| 开篇叙事 hook 当契约 | "写给谁"和"读完能做什么"两句都必须在场 |
| 篇末"本篇要点" bullet 交差 | 要点是回忆，交付物是能拿走用的（清单/表/模板） |
| 人物只在别的篇出场 | 每篇独立机检，本篇零出场就是不出件 |
| 篇末贴一行素材清单凑锚定 | 清单行只算 1 锚点，正文分散标注才算数 |
| 引用了素材但没标出处 | 「（出处：L3/科学网）」这类标注要落在论断旁 |
