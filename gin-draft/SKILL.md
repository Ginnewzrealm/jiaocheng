# gin-draft：按契约写教程

读取大纲、对应答案卡与来源。以读者完成任务为主线；篇首明确写给谁和读完能做什么。H2 标题及顺序与大纲一致，每节实现“干什么”而非只复述素材。

v3 正文使用脚注引用结论：`关键判断。[^C-001]`，篇末定义 `[^C-001]: [来源名称](实际URL)，适用范围。`。ID 来自答案卡 claims，并出现在大纲指定的小节。只写“研究表明”不能替代可解析证据。内部 L 路径不贴进正文。

操作步骤用隐藏标记绑定稳定 ID，并保留动作、预期结果、验证方法、失败处理：

```markdown
<!-- step:write-config -->
1. 写入配置。

预期结果：配置文件出现在指定位置。
验证方法：执行大纲指定的状态查询。
失败处理：按权限或版本错误进入对应排查分支。
```

关键措辞与大纲同步；修改步骤或条件时先更新施工单再验收。不要照抄占位示例。命令代码块标明语言，区分输入与预期输出，保留可复制格式。

写出契约中的前置条件、失败边界、成功判据、练习（如有）和交付物。篇末给清单、表格或模板。FAQ 只能使用上游有答案、有证据的问题，不能把发现了问题当作已有答案。

风格按原型选择：操作／排错型直接清楚；概念型解释并检验迁移；实战型仅叙述真实发生的经验。人物、反问、回环都是选择。数值精度服从证据，不为显得具体而编造个位数。

```bash
python3 scripts/draft.py check --file chapters/article-id.md --outline outlines/大纲_问题.json --manifest answers/answers-manifest.json --library library --output checks/article-id.draft.json
```

v3 检查核对契约、结论引用、快照、H2 顺序和基础构件。旧接口 --materials/--case 保留给历史稿诊断；旧素材锚定率只是该接口的样式启发式，不能作为证据可靠性或新版流水线验收。

完成稿交 gin-qc 做实际结果记录、呈现检查及人工审阅。输入改变后重跑检查，不手改报告让它变绿。
