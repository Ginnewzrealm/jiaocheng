# v3 单篇大纲契约

人读件 outlines/大纲_问题.md：标题、目录表（小节／这一节干什么）、写给、读完能、前置条件和成功标准，不显示内部 ID 或资料库路径。

机读件 outlines/大纲_问题.json：

```json
{
  "schema_version": 3,
  "article_id": "configure-tool",
  "问题": "如何配置工具？",
  "标题": "完成工具的单用户配置",
  "类型": "方法型",
  "tutorial_type": "操作型",
  "写给": "已经安装工具、但尚未完成配置的人",
  "读完能": "能完成配置并验证作用范围",
  "前置条件": ["已安装工具且可打开终端"],
  "适用范围": "单用户部署",
  "环境": {"工具版本": "实际版本", "平台": "实际平台"},
  "成功标准": [{"criterion_id": "K-1", "描述": "配置生效", "验证方法": "执行状态查询", "预期结果": "可观察的具体输出"}],
  "失败边界": ["无权限时联系管理员，不直接扩大权限"],
  "交付物": ["已验证的配置文件"],
  "小节": [{
    "section_id": "configure", "节": 1,
    "标题": "写入并检查配置", "干什么": "完成配置并确认结果",
    "构件": "代码块", "证据": ["C-001"],
    "步骤": [{"step_id": "write-config", "动作": "具体动作", "预期结果": "可观察结果", "验证方法": "检查方法", "失败处理": "失败时下一步"}]
  }],
  "素材": ["L1/config.md"],
  "未采用": {}
}
```

示例值必须替换为实际项目事实，不能直接冒充达标产物。

- article_id 使用字母、数字、连字符或下划线，流水线内稳定不变。正文命名 chapters/article_id.md，报告使用相同 ID。
- 每节有唯一 section_id、非空标题／干什么及至少一个真实 claim_id，在对应卡的 claims 内解析，不再写“一句话答案”等泛字段。
- 类型沿用研究分类，tutorial_type 取六种原型之一。节数按任务决定。
- 操作／排错至少一个完整步骤，概念型另填非空练习文本数组。关键步骤、交付物和成功判据措辞保留到正文；改措辞时同步施工单。
- 前置条件可为空数组；环境、范围、成功标准、失败边界、交付物必须明确。无特殊失败条件时说明不适用原因。
- 构件取 无／步骤表／对比表／提示块／代码块。未知构件不静默透传。
- 旧件没有 schema_version；补齐真实证据和契约后升级为 3，不自动补写验证结果。

改协议同步校验器、生产者／消费者与集成测试。检查报告放 checks，避免被扫描成第二篇大纲。
