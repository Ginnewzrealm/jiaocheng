# 标准输出模板（gin-outline）

> 大纲的标准产出格式。机检锁死此格式；改格式 = 改本文件 + 同步 outline.py + 回归测试。

## 1. 交付物（一卡两份）

```
<输出目录>/
├── 大纲_<slug>.md     ← 人读：目录表（用户审核件）
├── 大纲_<slug>.json   ← 机读：施工件（Stage 5 按图施工）
└── 大纲一览.md        ← （多卡时）所有文章的标题+写给+读完能清单，系列导航用
```

slug = 卡片"问题"原文（保持原问句，便于追溯）。

## 2. 大纲_<slug>.md 模板（审核件）

```markdown
# <文章标题：从问题原文来，可轻度口语化>

| # | 小节标题 | 这一节干什么 |
|---|---|---|
| 1 | <人话标题> | <施工说明：这一幕演什么、给读者什么> |
| 2 | ... | ... |
| N | <回收开头的标题> | <回到开场场景，回答开场问题> |

写给：<一句具体画像，含"会什么、卡在哪">
读完能：<"能"字头的可检验动作>
```

**铁律**：
- .md 里**不得出现**素材文件路径、`L3/xxx.md`、卡片 ID 等施工标记——那是 json 的事。
- 表格行序 = 阅读顺序 = 成稿 H2 顺序。
- 最后一节必须回收开头场景。

## 3. 大纲_<slug>.json 模板（施工件）

```json
{
  "问题": "<答案卡的问题原文，必须在 manifest 中真实存在>",
  "标题": "<成稿标题，与 .md 的 # 一致>",
  "类型": "<答案卡的类型：事实型|方法型|争议型>",
  "写给": "<与 .md 一致>",
  "读完能": "<与 .md 一致>",
  "贯穿人物": "<可选：开场人物名，如 小张>",
  "小节": [
    {
      "节": 1,
      "标题": "<与 .md 表格该行一致>",
      "干什么": "<施工说明，与 .md 一致>",
      "证据": ["<卡片出处ID或字段名，≥1 条>"]
    }
  ],
  "素材": ["<从卡片"出处"字段继承的相对路径，须是文件>"],
  "未采用": {"<卡片问题>": "<弃用理由>"}
}
```

**字段规则**：
- `小节` 5–8 条；每条 `干什么` 非空，`证据` ≥1。
- `素材` 直接从卡片"出处"的本地文件继承；联网来源（有 url 无本地文件）不进素材，已随卡片入库的在库内。
- 单卡模式 `未采用` 恒为空 `{}`；多卡显式立项时才允许弃用条目。

## 4. 填法示例（减脂·篇二：热量缺口）

```markdown
# 减肥时热量缺口，到底该留多少？

| # | 小节标题 | 这一节干什么 |
|---|---|---|
| 1 | 先算一笔身体的账 | 小张 3 斤得而复失开场，引出"不知道身体花多少，就没资格谈少吃多少" |
| 2 | 你一天到底消耗多少 | TDEE 三构成（大头是基础代谢），活动系数怎么乘，算出读者自己的数 |
| 3 | 选多大的缺口才合适 | 三档对照 200-300/300-500/600+ 的速度与代价，标准答案 300-500 |
| 4 | 别减掉肌肉 | 两个保肌杠杆：蛋白质 1.6-2.2 g/kg + 力量训练，缺一个就瘦胖子 |
| 5 | 填出你的缺口计算器 | 动手填模板：TDEE − 选定缺口 = 每日目标摄入，两杠杆勾选 |
| 6 | 回到小张那 2 斤反弹 | 拆解：水分回流 + 没缺口纪律，不是"代谢坏了" |

写给：打算开始控制饮食、但从没算过账的减肥者
读完能：能算出自己的 TDEE 并设定每日 300-500 大卡缺口
```

对应 json 的小节[1]：`{"节": 1, "标题": "先算一笔身体的账", "干什么": "小张 3 斤得而复失开场，引出…", "证据": ["一句话答案", "出处"]}`，素材继承卡片"出处"里的 5 份库内文件路径。
