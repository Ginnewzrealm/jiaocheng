# 教程原型

研究分类回答“怎么研究”；教程原型回答“读者拿它完成什么”。选择一个主原型，可局部混合，但成功标准须一致。

| tutorial_type | 任务 | 建议骨架 | 有效性证据 |
|---|---|---|---|
| 操作型 | 完成具体操作 | 目标／前置条件 → 步骤 → 验证 → 失败处理 | 环境、实际输出或产物记录 |
| 排错型 | 定位并修复故障 | 症状 → 候选原因 → 区分测试 → 修复 → 回归确认 | 观察能区分原因，原故障消失 |
| 概念型 | 建立可迁移的理解 | 场景 → 心智模型 → 示例与反例 → 边界 → 练习 | 新例子的解释或作答记录 |
| 对比型 | 比较方案 | 场景 → 维度与证据 → 差异 → 适用条件 | 同口径比较、覆盖关键约束 |
| 决策型 | 选择方案 | 目标 → 约束 → 选项 → 分支 → 建议 | 样例条件得到可解释选择 |
| 实战型 | 重建一个案例 | 目标 → 方案 → 过程 → 实际失败 → 复盘 | 重建关键结果及边界 |

操作／排错须声明完整步骤，概念型须声明迁移练习。其他类型同样要提供检查方法和结果记录，不能只打主观总分。

不强求讲故事、贯穿人物、疑问句或回扣开头。概念标题可命名概念；操作指南可用祈使句。所有原型都应交代成立条件和下一步，避免把领域偏好变成全局硬规则。
