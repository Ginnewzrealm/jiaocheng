# 教程大纲方法论（gin-outline 知识库）

> 本文件是"怎么写出一份好教程大纲"的方法论，被 SKILL.md 与机检共同引用。
> 改大纲写法 = 改本文件对应小节 + 同步机检规则，不要只改口头约定。
> 融合来源：course-outline-design（五决策/动词化）、Socialpranker synthesis_outline
> （章节→claims 映射）、yao-tutorial-skill（hook/promise/checkpoint）、
> 2026-09-06 减脂实战三轮评审（用户拍板"一题一文/目录表/标题人话"）。

## 0. 基本定位

- **一题一文**：一张达标卡 = 一篇文章。禁止把多张卡凑进一篇（那是"综述/教程书"，需用户显式指令+另行拍板）。
- 大纲有两张脸：`大纲.md` 是**给读者/用户审核的目录**（素材隐身），`大纲.json` 是**给 Stage 5 的施工件**（素材对账）。同一份判断，两种呈现。
- 大纲不是写作计划，是"找到的"重组：每节有证据支撑、每个证据有去处。

## 1. 三决策（动笔前钉死，缺一不可）

| 决策 | 写法 | 反例 |
|---|---|---|
| 写给谁 | 一句具体画像，含"他现在会什么、卡在哪" | "新手"（太泛，不通过） |
| 读完能 | "能"字头的可检验动作，一篇一个 | "能了解减重和减脂的区别"（"了解"不可测，不通过） |
| 节数与节奏 | 5–8 节，一节一个动作；开头场景、中间递进、结尾回收 | 一节塞两个动作；少于 5 节（内容单薄）多于 8 节（切碎） |

贯穿案例降级为**可选**：单篇短文用"小张"式开场人物带一带即可，不强求全文贯穿；跨篇系列可共享同一个人物，靠各自开头回调。

## 2. 目录表条目（.md 审核件的每一行）

每行三列：

| 列 | 内容 | 要求 |
|---|---|---|
| 小节标题 | 人话，真人会这么念的表达 | 见 §3 标题写法 |
| 这一节干什么 | 施工说明：这一幕演什么、给读者什么、挂哪条证据 | 不许空；术语随便用（这是给作者的，不是给读者的） |
| 证据 | 卡片内证据 ID（不进 .md 表，只在 json） | 每节 ≥1 条，见机检 |

行序 = 阅读顺序 = 成稿 H2 小标题顺序。

## 3. 标题写法（人话化的具体规则）

1. **自然带动作，不硬凑动词开头**。"选定合适的热量缺口"✅；"选定缺口档位"❌（术语当宾语，真人不说）；"热量缺口"❌（纯名词）。
2. **主语优先用"你"或具体人物**，让读者有代入："你一天到底消耗多少" ✅。
3. **一个标题一个动作**；需要铺垫的动作拆两节。
4. 允许问句标题（"到底该留多少？"），问句天然带动作感。
5. 禁用判定交给机检：纯名词标题、术语堆砌（动词+术语词组合如"档位/杠杆/映射"直接作宾语时警告）。

**动词化规定的正确理解**：course-outline-design 的"标题动词化"治的是"名词标题看不出要干嘛"，不是要求语法上的动词开头。判据是"**读者秒懂这节干嘛**"，不是词性。

### 篇名公式（§3.5，2026-09-12 调研批次：标题公式 best practices）

节标题之外，篇名（成稿 H1）另有公式：**篇名 = 具体动作 + 对象 +（可选量化/结果承诺）**。

- ✅ "3 步算出你的热量缺口"、"减肥总反弹？先看懂水分和脂肪"
- ❌ "热量缺口详解"、"减脂指南大全"、"关于热量缺口"——文档腔，不是教程腔
- 判据不变："真人会点进去的标题"。量化承诺要兑现，不许标题党。

机检 ⚠️：篇名以 大全/详解/浅析/概述/白皮书/圣经 收尾。

## 4. 节序原则（认知负荷的落地）

1. **开头必须是具体场景/痛点，不是概念定义**。读者先来后理——先让他"在场"，再给他名词。（反例：第一节就叫"什么是热量缺口"）
2. **一节一个台阶**：每节回答一个问题，且这个问题是读者**读完上节自然长出来的**。
3. **动作章结构**：场景 → 方法 → 动手 → 回收。知识章结构：场景 → 拆概念 → 判别工具 → 回收。
4. **结尾回收开头**：最后一节必须回到开头的场景/人物，回答开场抛出的问题（回环呼应，契诃夫之枪）。
5. 顺序类型默认：认知（是什么/为什么）→ 方法（怎么做）→ 判断（怎么辨）。一篇只承担一个类型为主，不硬凑三段式。

## 4.5 构件分配（2026-09-12 调研批次：真实教程的排版构件）

真实教程的呈现不止散文。排大纲时顺手给每节分配**构件**（json 可选"构件"字段），Stage 5 按构件施工：

| 节特征 | 构件 | 施工方式（Stage 5） |
|---|---|---|
| 方法节（怎么做，动作 ≥2 步） | 步骤表 | 有序列表，每项动作开头："算出你的 TDEE"✅ "TDEE 的计算"❌ |
| 含多档参数/多方案对照 | 对比表 | markdown 表格，维度 ≥2 列 |
| 含坑/反常识/易错点 | 提示块 | 引用块 + `**注意**：` / `**坑**：` 前缀 |
| 含命令/配置/可复制内容 | 代码块 | 围栏标语言，内容可直接复制 |
| 其余（默认） | 无 | 纯散文 + H2 |

- 一节一个主构件；构件是**呈现**建议，不替代"干什么"施工说明。
- 机检：未知构件值 ❌（格式锁死，合法值：无/步骤表/对比表/提示块/代码块）；不分配不拦（缺省=无，渐进路线）。

## 5. 详略判断

- 卡片内容厚、读者门槛高的节 → 拆两节（如 TDEE 计算+档位选择可拆）。
- 卡片内容薄的点 → 并进相邻节，不单独撑节。
- 每节"干什么"列写不出一句具体场景/动作时，说明该节不存在——删。
- 系列内互挂：一篇显式调用前篇判据时，在"干什么"列写明"调用篇X第N节的××判据"，并保证前篇真实存在（机检查）。

## 6. 证据与可追踪

- 每节至少挂 1 条卡片内证据（出处 ID 或卡片字段）。
- json 里素材路径从答案卡"出处"字段继承，**不再另挑素材**（v1 的"每章挑素材"是重复劳动，出处已在卡片里核过）。
- 达标卡必须被用到；弃用须在给用户的汇报里给理由（机检：全部弃用=脱节，拦）。

## 7. 机检规则 ↔ 方法论条目对照

| 机检规则 | 对应方法论条目 |
|---|---|
| 素材文件存在且是文件 | §6 |
| 卡片必须真实在 manifest | §0/§6 |
| 每节必须有"干什么"施工说明 | §2 |
| 标题人话化（禁纯名词/术语堆砌） | §3 |
| 篇名文档腔后缀（大全/详解/浅析 ⚠️） | §3.5 |
| 构件合法值锁死（未知 ❌） | §4.5 |
| 写给/读完能必填，读完能须"能"字+动作 | §1 |
| 开头非概念（首行不得是定义式标题） | §4.1 |
| 每节 ≥1 证据 | §6 |
| 达标卡全弃用=脱节 | §6 |

## 8. 常见错误（来自实战）

| 错误 | 纠正 |
|---|---|
| 把素材路径写进 .md 目录表 | 素材只在 json；.md 只留人话 |
| 多卡凑一篇"大教程" | 一题一文；要综述就显式立项 |
| 标题凑动词变成术语腔 | 判据是"真人会这么说"，不是词性 |
| 开头第一节下定义 | 先场景后概念 |
| 结尾不回收开头 | 最后一节必须回开场场景 |
| 沿用 v1 的"知识章/动作章排序"机检 | 已删——那是多章教程的概念，一题一文用 §4 的节序 |
