# gin-outline：教程大纲设计

输入一个主题（已拍板）→ 输出教程大纲（章节 = 答案卡 × 素材文件 × 学习路径）。
核心原则：**大纲不是写作计划，是"找到的"重组——每章有卡支撑、每卡有去处、
顺序对新手友好。判断全部机检可追溯。**

方法论来源：Socialpranker 综合大纲的 section↔claims 映射 + 机检哲学；
course-outline-design 的五决策钉死；Sweller 认知负荷理论的排序依据。

## 何时使用 / 不适用

- 主题已定（用户拍板）、答案卡库在手，要排教程结构 → 本技能
- 还没决定写什么主题 → 不是本技能的事（用户拍板后才进来）
- 缺答案 → 跑 gaps 出缺口清单交用户，回 gin-answer 补做（本技能不内嵌补做）

## 工作流程

```
1. 召回    从 answers-manifest 挑与主题相关的达标卡（主题词 shingles 匹配）
2. 缺口    python3 scripts/outline.py gaps --manifest <m> --problems <p> --topic <t>
           → 主题相关但无卡覆盖的问题清单（外置，交用户决定是否回 gin-answer）
3. 素材    为每章从资料库挑素材文件（答案卡给"讲什么"，素材给"用什么讲"）
4. 组装    写大纲 .md + .json：章节→卡片+素材映射，排学习路径
           必钉死（动笔前）：目标读者、贯穿案例（一个贯穿全教程的案例/人物）
5. 机检    python3 scripts/outline.py check --outline <o> --manifest <m> --library <lib>
           → errors 不归零不许交付
```

## 大纲 .json schema

```json
{
  "主题": "...", "目标读者": "...",
  "贯穿案例": "一个贯穿全教程的案例/人物（五决策之一，机检必填）",
  "章节": [
    {"章": "章节标题（用问题清单里的用户提问句式更抓人）",
     "目标": "能+动作动词（能判断/能执行/能计算）或含定义/原理标记的知识目标",
     "卡片": ["答案卡的'问题'原文（须在 manifest 中真实存在）"],
     "素材": ["资料库相对路径 L3/xx.md（须是文件，目录凑数会被拦）"]}
  ],
  "未采用卡片": ["达标但没用的卡"],
  "未采用理由": {"<问题原文>": "弃用理由（必填，弃用也是判断）"}
}
```

## 机检规则（全部来自红阶段基线实测，2026-09-06）

| 规则 | 级别 | 失败样本 |
|---|---|---|
| 素材文件必须存在且是文件 | ❌ | 幽灵引用/目录路径凑数 |
| 卡片必须真实在答案卡库 | ❌ | 引用库里没有的问题 |
| 每章必须有目标 | ❌ | 基线四章全缺目标 |
| 目标必须动作动词（"能/会+了解/概念"是知识目标伪装，单独拦） | ❌ | 想拿"能了解"蒙混 |
| 知识章不得排在动作章之后（先备知识拓扑） | ❌ | 脚踩西瓜皮排法 |
| 同一张卡映射 ≥3 章且过半 → 注水 | ⚠️ | 基线一张卡映射 4/4 章 |
| 达标卡必须被用到，弃用须给理由；全部弃用 = 脱节，拦 | ⚠️/❌ | synthesis gap（答案白找） |
| 贯穿案例必填 | ❌ | 五决策没钉死 |

## 排序依据（CLT 内在负荷管理）

- 知识章（定义/原理/机制）在前，动作章（执行/计算/判断）在后
- 单章素材 ≤4 份（外在负荷：一章别塞太多料）
- 章节目标用读者视角的动作动词，不用"了解/学习/掌握"开头

## 常见错误（红阶段基线实测）

| 错误（基线实际行为） | 纠正 |
|---|---|
| 一张卡映射所有章节 | 一章一角度；同卡复用须注明不同要点角度 |
| 缺口清单随手写空 | 必跑 gaps 命令，主题 shingles 召回是确定性判定 |
| 章节标题用学术分类 | 从 problem_list 抄用户的原始提问句式 |
| 素材凭印象写路径 | 相对路径 + check 机检存在性 |
| 弃用卡片不说明 | 未采用理由必填，弃用也是判断要可追溯 |
