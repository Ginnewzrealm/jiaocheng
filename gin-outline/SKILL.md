# gin-outline：单篇教程大纲设计

输入一张达标答案卡（主题已拍板）→ 输出一份**目录表式大纲**。
核心原则（2026-09-06 v2 改造，用户三轮评审拍板）：

- **一题一文**：一张达标卡 = 一篇文章。禁止多卡凑一篇。
- **大纲有两张脸**：`大纲.md` 是给用户审核的目录（素材隐身，不得出现路径/卡片ID）；
  `大纲.json` 是给 Stage 5 的施工件（素材对账、证据挂载）。同一份判断，两种呈现。
- **大纲不是写作计划，是"找到的"重组**：每节有证据支撑、每个证据有去处。

方法论文库：`references/outline-methodology.md`（怎么写好一份大纲——改写法先改它）；
输出模板：`references/output-templates.md`（md/json 标准格式，机检锁死）。

## 何时使用 / 不适用

- 主题已定（用户拍板）、答案卡库在手，要排文章结构 → 本技能
- 还没决定写什么 → 不是本技能的事（用户拍板后才进来）
- 缺答案 → 跑 gaps 出缺口清单交用户，回 gin-answer 补做（本技能不内嵌补做）

## 工作流程

```
1. 召回    从 answers-manifest 挑与主题相关的达标卡（主题词 shingles 匹配）
2. 缺口    python3 scripts/outline.py gaps --manifest <m> --problems <p> --topic <t>
           → 主题相关但无卡覆盖的问题清单（外置，交用户决定是否回 gin-answer）
3. 三决策  动笔前钉死（缺一不写）：写给谁（具体画像，"新手"不算数）、
           读完能（"能"字头的可检验动作，一篇一个）、节数与节奏（5-8 节）
4. 排目录  按 methodology §4 节序写目录表：开头具体场景（非定义）→ 一节一台阶
           → 结尾回收开头。标题按 §3 人话化（判据是"真人会这么念"，不是词性）
5. 组装    写大纲_<slug>.md（审核件）+ 大纲_<slug>.json（施工件，按 output-templates.md）
           素材直接从卡片"出处"继承，不再另挑
6. 机检    python3 scripts/outline.py check --outline <o> --manifest <m> --library <lib>
           → errors 不归零不许交付；⚠️ 须逐条向用户说明
7. 交付    把 .md 目录表【内嵌粘贴】给用户确认（硬闸门，只给文件路径不算交付）
```

## 机检规则 ↔ 方法论条目

| 规则 | 级别 | 方法论 |
|---|---|---|
| v1 多章格式（"章节"键）一律拒绝并指路模板 | ❌ | §0 一题一文 |
| 卡片问题必须真实在 manifest 且状态=达标 | ❌ | §0/§6 达标卡才许施工 |
| 素材必须存在且是文件（目录凑数不行） | ❌ | §6 |
| 每节"干什么"施工说明非空 | ❌ | §2 空标题不许进目录 |
| 每节 ≥1 条卡片证据 | ❌ | §6 |
| 定义式标题（什么是X / X的定义 / X是什么） | ❌ | §4.1 开头必须场景非概念 |
| 标题以术语词收尾（档位/杠杆/映射/拓扑/范式…） | ⚠️ | §3 真人不会这么念 |
| 写给必填且非"新手/初学者/小白" | ❌ | §1 三决策 |
| 读完能必填、以"能"开头、非知识动词（能了解/理解→❌） | ❌ | §1 三决策 |
| 小节数 5–8 | ⚠️ | §1 三决策 |

## 标题怎么写（§3 摘要，细节见方法论）

1. 自然带动作，不硬凑动词开头："选定合适的热量缺口"✅；"选定缺口档位"❌
2. 主语优先"你"或具体人物："你一天到底消耗多少"✅
3. 一节一个动作；要铺垫就拆两节
4. 允许问句标题
5. 判据是"真人会这么说"——不是词性检查

## 常见错误（方法论 §8 摘要）

| 错误 | 纠正 |
|---|---|
| 把素材路径/卡片ID写进 .md 目录表 | 素材只在 json；.md 只留人话 |
| 多卡凑一篇"大教程" | 一题一文；要综述显式立项 |
| 标题凑动词变成术语腔 | 判据是"真人会这么说" |
| 开头第一节下定义 | 先场景后概念 |
| 结尾不回收开头 | 最后一节必须回开场场景 |
| 沿用 v1 的"知识章/动作章排序"机检 | 已删——多章概念，一题一文用 §4 节序 |
